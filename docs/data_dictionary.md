# Data dictionary and relational model

All dates use ISO 8601. Monetary amounts are decimal strings rounded to two decimal places in the synthetic examples; production systems should use fixed-point/DECIMAL database columns, not binary floating point. Blank optional references are empty strings in CSV. IDs are immutable and zero-padded where specified.

## Entities and key relationships

| Entity | Primary key | Important foreign keys | Cardinality / lifecycle |
|---|---|---|---|
| Merchant | `merchant_id` | — | Merchant 1:N PaymentOrder; active/inactive; effective dates support history |
| PaymentOrder | `payment_id` (`PAY-YYYY-########`) | `merchant_id` | Merchant 1:N orders; order 1:N attempts; created/authorized/captured/failed/refunded are lifecycle examples |
| PaymentAttempt | `attempt_id` (`ATT-<payment-id>-NN`) | `payment_id` | Order 1:N attempts; created/authorized/captured/failed/refunded |
| ProcessorEvent | `processor_event_id` | `attempt_id` | Attempt 1:N events; immutable event history; `idempotency_key` identifies repeated delivery |
| SettlementBatch | `batch_id` (`SET-YYYY-######`) | — | Batch 1:N SettlementLine; pending/settled/failed |
| SettlementLine | `settlement_line_id` (`STL-<batch-id>-NNN`) | `batch_id`, `processor_event_id` | Batch 1:N lines; processor event can be referenced by settlement lines; uniqueness of event-per-batch should be validated, while labelled duplicate cases are retained |
| BankStatementLine | `bank_line_id` (`BANK-YYYY-######`) | — | Each line is independently imported from a statement; optional match to a batch through ReconciliationMatch |
| ReconciliationMatch | `reconciliation_id` (`REC-YYYY-######`) | `bank_line_id`, `batch_id` | Bridge/decision record connecting bank lines and batches; conceptually N:M across reconciliation runs, with one-to-one consumption enforced per run |
| Exception | `exception_id` | optional `bank_line_id`, optional `batch_id` | One source record may create multiple exceptions over time; open/under_review/resolved/closed |
| Resolution | `resolution_id` | `exception_id` | Exception 1:N resolution history; pending_review/adjusted/accepted_as_timing_error/escalated; never overwrite prior resolutions |

## Field-level definitions

The CSV files generated by this project use these fields. `required` means populated for ordinary generated records; intentionally optional fields are blank when no relationship or resolution exists. Enum values shown are examples/allowed generator values.

### Merchant.csv
| Field | Type | Required | Constraints / validation |
|---|---|---|---|
| merchant_id | string | Yes | Unique PK, `MER-` plus seven digits |
| merchant_name | string | Yes | Non-empty display name |
| country | string | Yes | ISO-like two-letter synthetic code |
| default_currency | string | Yes | One of USD/EUR/GBP/INR |
| status | enum | Yes | active/inactive |
| effective_from | date | Yes | ISO date; <= effective_to when end date exists |
| effective_to | date/string | No | Blank means currently effective; otherwise >= effective_from |

### PaymentOrder.csv
| Field | Type | Required | Constraints / validation |
|---|---|---|---|
| payment_id | string | Yes | Unique PK, `PAY-2026-` plus eight digits |
| merchant_id | string | Yes | FK to Merchant |
| amount | decimal string | Yes | > 0; major currency units |
| currency | enum/string | Yes | USD/EUR/GBP/INR |
| created_at | datetime | Yes | ISO date-time |
| status | enum | Yes | created/authorized/captured/failed/refunded |

### PaymentAttempt.csv
| Field | Type | Required | Constraints / validation |
|---|---|---|---|
| attempt_id | string | Yes | Unique PK, `ATT-<payment_id>-NN` |
| payment_id | string | Yes | FK to PaymentOrder |
| attempt_no | integer | Yes | Positive sequence per payment |
| status | enum | Yes | created/authorized/captured/failed/refunded |
| amount | decimal string | Yes | >= 0 and consistent with order amount in this generator |
| currency | enum/string | Yes | Must match parent order in baseline |
| created_at | datetime | Yes | ISO date-time; not before order creation |

### ProcessorEvent.csv
| Field | Type | Required | Constraints / validation |
|---|---|---|---|
| processor_event_id | string | Yes | Unique PK; event identity, not delivery identity |
| attempt_id | string | Yes | FK to PaymentAttempt |
| event_type | enum/string | Yes | capture/refund/authorized/failed/created |
| event_status | enum/string | Yes | succeeded/created/authorized/failed/refunded |
| amount | decimal string | Yes | >= 0; refund signed treatment applied during settlement aggregation |
| currency | enum/string | Yes | Must match attempt for valid baseline events |
| event_at | datetime | Yes | ISO date-time; lifecycle order should be validated except labelled anomaly |
| idempotency_key | string | Yes | Detect duplicate webhook delivery; repeated keys must not double count |
| ingest_status | enum | Yes | accepted/duplicate/rejected |
| issue_type | string | No | Present only for deliberate labelled anomaly |

### SettlementBatch.csv
| Field | Type | Required | Constraints / validation |
|---|---|---|---|
| batch_id | string | Yes | Unique PK, `SET-2026-` plus six digits |
| processor_name | string | Yes | Non-empty processor identifier |
| currency | enum/string | Yes | One currency per batch |
| gross_amount | decimal string | Yes | Sum of signed settlement lines |
| fee_amount | decimal string | Yes | Non-negative sum of capture fees |
| net_amount | decimal string | Yes | `gross_amount - fee_amount` |
| line_count | integer | Yes | Count of linked settlement lines |
| settlement_date | date | Yes | ISO date; may be delayed relative to payment event |
| status | enum | Yes | pending/settled/failed |

### SettlementLine.csv
| Field | Type | Required | Constraints / validation |
|---|---|---|---|
| settlement_line_id | string | Yes | Unique PK, `STL-<batch_id>-NNN` (deliberate duplicate has explicit suffix) |
| batch_id | string | Yes | FK to SettlementBatch |
| processor_event_id | string | Yes | FK to ProcessorEvent |
| line_type | enum | Yes | capture/refund |
| amount | decimal string | Yes | Signed: captures positive, refunds negative |
| currency | enum/string | Yes | Must match batch and event currency for normal records |
| created_at | datetime | Yes | Derived from processor event time |
| issue_type | string | No | Used only on deliberately injected anomaly rows |

### BankStatementLine.csv
| Field | Type | Required | Constraints / validation |
|---|---|---|---|
| bank_line_id | string | Yes | Unique PK, `BANK-2026-` plus six digits |
| bank_account | string | Yes | Non-empty synthetic account label |
| reference | string | Yes | Expected to refer to settlement batch; may be deliberately unmatched |
| amount | decimal string | Yes | Signed bank movement in major currency units |
| currency | string | Yes | Expected to match settlement currency; mismatches are exceptions |
| booking_date | date | Yes | ISO date |
| value_date | date/string | No | Blank when unavailable |
| description | string | Yes | Statement narrative |
| source_file | string | Yes | Synthetic source filename |

### ReconciliationMatch.csv
| Field | Type | Required | Constraints / validation |
|---|---|---|---|
| reconciliation_id | string | Yes | Unique PK, `REC-2026-` plus six digits |
| bank_line_id | string | Yes | FK to BankStatementLine |
| batch_id | string | Yes | FK to SettlementBatch |
| match_status | enum | Yes | matched/partial/unmatched |
| match_method | string | Yes | reference_amount_currency in baseline |
| amount_difference | decimal string | Yes | bank amount minus settlement net |
| evaluated_at | datetime | Yes | Reconciliation evaluation timestamp |

### Exception.csv
| Field | Type | Required | Constraints / validation |
|---|---|---|---|
| exception_id | string | Yes | Unique PK, `EXC-` plus seven digits |
| bank_line_id | string | No | FK to BankStatementLine when bank-originated |
| batch_id | string | No | FK to SettlementBatch when a batch was identified |
| exception_type | string/enum | Yes | unmatched_bank_or_settlement/amount_mismatch/currency_mismatch/duplicate_bank_match |
| severity | enum | Yes | low/medium/high |
| status | enum | Yes | open/under_review/resolved/closed |
| created_at | datetime | Yes | ISO date-time |

### Resolution.csv
| Field | Type | Required | Constraints / validation |
|---|---|---|---|
| resolution_id | string | Yes | Unique PK, `RES-` plus seven digits |
| exception_id | string | Yes | FK to Exception |
| resolution_action | enum/string | Yes | pending_review/adjusted/accepted_as_timing_error/escalated |
| resolution_note | string | Yes | Non-empty audit explanation |
| resolved_by | string | No | Reviewer/system actor identifier |
| resolved_at | datetime | No | Required when outcome is final |
| outcome | enum | Yes | pending/resolved/rejected/escalated |

## Ground truth
`ground_truth.csv` is an evaluation-only sidecar with `record_type`, `record_id`, `issue_type`, `ground_truth`, and `expected_reason`. Do not join these labels into model/rule input features. The generator uses no external dataset; `source_manifest.json` records the seed, parameters, row counts and checksums.
